第 5 章｜部署 LINE Bot 至 Vercel

5-1 設定環境變數

前往 vercel.com/drop，上傳課程 ZIP、確認帳號範圍與 Project name，建立 Project 後逐筆加入六個環境變數，再 Redeploy。

進階篇8 分鐘提供完整範本

下載課程 ZIP查看範本說明開啟 Vercel Drop

你不需要本機開發環境直接使用課程提供的 Python 正式版；不需要 Git、GitHub、Vercel CLI、Python、venv、pip、ngrok，也不需要在本機啟動 Flask。請不要修改程式碼、Sheets schema、Gmail 或 Webhook 架構。

用 Vercel Drop 建立 Project

  1. 下載課程 ZIP

    按下方按鈕下載 LINE訊息整理Bot_課程正式版.zip。ZIP 根目錄直接包含 app.py、index.py、requirements.txt、vercel.json 與其餘正式 Python 檔案；不含真實 .env 或 Service Account JSON。ZIP 可以直接上傳，不用先解壓縮。

    下載課程 ZIP

  2. 開啟 Vercel Drop

    前往 vercel.com/drop → 按 Log In／登入 → 選擇你的登入方式並完成驗證。登入後回到 Drop 上傳區。

    開啟 Vercel Drop

  3. 上傳 ZIP 或 folder

    把課程 ZIP 拖進上傳區，或按上傳區選取檔案。Drop 接受 ZIP 或 folder；若你已解壓縮，也可選擇直接看得到 app.py 的資料夾。等待 Vercel 讀取完成，不要上傳 Service Account JSON。

  4. 確認 Team／個人帳號

    若畫面顯示 Team／Scope 選擇器，選擇你要持有此 Project 的 Team 或個人帳號。個人練習通常選個人帳號；公司 Team 請遵守管理政策。不同帳號與方案可能不顯示這一欄，未顯示時直接使用目前登入範圍。

  5. 設定 Project name 並 Deploy

    若畫面提供 Project name，輸入例如 line-project-memory-bot；名稱需符合 Vercel 當下規則。其他 Framework Preset／Root Directory 若出現，使用自動偵測或維持預設 → 按 Deploy。第一次因尚未設定環境變數而失敗可以接受；重點是 Project 已建立。

    你現在應該看到Vercel 已進入新 Project 的 Overview／Deployment 畫面，頂端顯示 Project name。即使第一個 Deployment 失敗，也要留在這個 Project 設定，不要重新 Drop ZIP。
不要重新 Drop ZIPVercel Drop 每次重新 Drop 都會建立新的 Project。正確順序是：第一次 Drop ZIP → 建立 Project → 設定六個 Environment Variables → Redeploy 原本 Project。環境變數填錯或更新時，也是在原 Project 修正後 Redeploy，不要再次 Drop。

填入六個環境變數

  1. 開啟 Environment Variables

    目前 Vercel Project → 頂端 Settings → 左側 Environment Variables → Add New。每個變數都在 Name 填名稱、Value 貼真正的值；Environment 至少選 Production → 按 Save，再新增下一筆。

  2. 貼入正式六個變數

    Name 大小寫必須完全一致；只有以下六個：

    環境變數名稱清單
    LINE_CHANNEL_SECRET
LINE_CHANNEL_ACCESS_TOKEN
GMAIL_ADDRESS
GMAIL_APP_PASSWORD
GOOGLE_SHEET_ID
GOOGLE_SERVICE_ACCOUNT_BASE64

    Vercel 的 Value 欄只貼真正的值。錯誤：LINE_CHANNEL_SECRET=abc123；正確：只貼 abc123。不要加雙引號、不要加單引號、不要帶變數名稱、不要帶前後空白，也不要多貼換行。

NameValue 前面在哪裡取得
LINE_CHANNEL_SECRET4-2：LINE Developers → Channel → Basic settings → Channel secret；前後不可有多餘空白
LINE_CHANNEL_ACCESS_TOKEN4-2：Channel → Messaging API → Channel access token (long-lived)
GMAIL_ADDRESS4-3：建立 App Password 的完整寄件 Gmail 地址
GMAIL_APP_PASSWORD4-3：Google App Password 畫面顯示的 16 碼；移除顯示用空格，不是一般登入密碼
GOOGLE_SHEET_ID4-3：Sheets URL 的 /d/ 與 /edit 之間，不能填整條網址
GOOGLE_SERVICE_ACCOUNT_BASE644-3／本頁：自己的 Service Account JSON 以 PowerShell 轉成的單行 Base64
你現在應該看到Environment Variables 清單恰好有上述六個 Name，且每一筆都包含 Production。Value 可能被遮蔽是正常的；逐筆核對名稱，不要用眼睛猜字串內容。

在本頁產生並貼上 Base64

  1. 確認 JSON 實際檔名與完整路徑

    在檔案總管找到原始 Service Account JSON，確認 JSON 的實際檔名與完整路徑。在檔案所在資料夾空白處按右鍵 → 在終端機中開啟，或在位址列輸入 powershell 後按 Enter。

  2. 產生剪貼簿內容

    把下列 完整JSON路徑 換成你的實際完整路徑後執行：

    Windows PowerShell｜產生並複製
    [Convert]::ToBase64String([IO.File]::ReadAllBytes("完整JSON路徑")) | Set-Clipboard

    PowerShell 沒有顯示大量文字是正常的，因為結果已直接複製到剪貼簿。

  3. 立即貼入 Vercel

    立即前往 Vercel，把剪貼簿內容貼入 GOOGLE_SERVICE_ACCOUNT_BASE64 的 Value。貼入 Vercel 前不要再複製其他文字，否則剪貼簿內容會被覆蓋；若已被覆蓋，重新執行 PowerShell 指令即可。

    可以自行切換 Vercel Value 的顯示／遮蔽狀態，確認已貼入一整串很長的 Base64 字串，但這不代表 Base64 有效性的技術驗證。最終是否設定正確，以部署與實際 Google Sheets 寫入測試為準。

Base64 是編碼，不是加密Base64 和原始 JSON 同等敏感。不可公開、不可提交 GitHub、不可貼到公開聊天或任何線上 Base64 converter，也不可放進教材、影片或截圖。

套用設定

  1. Redeploy

    六個環境變數都 Save 後，若 Settings 出現「Redeploy」提示可直接按；否則到原本 Project → Deployments → 最新一筆右側省略號選單 → Redeploy → 在確認視窗再次按 Redeploy。只有新 Deployment 會取得新設定；不要重新 Drop ZIP。

    你現在應該看到Deployments 出現一筆新的執行紀錄，完成後狀態為 Ready。若失敗，先開啟 Deployment Logs 查看哪個設定缺失，再回 Settings 修正並 Redeploy。

部署卡關時的選用救援

先依上方正常 Vercel Drop 流程操作；只有卡住時才使用下方獨立實作輔助工具。它不是工作記憶 Prompt 1、2、3 的其中一步。

如何驗證成功

  • Vercel Project 已由 Drop 建立
  • Environment Variables 恰有六個正式名稱
  • GOOGLE_SHEET_ID 不是整條網址
  • GMAIL_APP_PASSWORD 不是一般登入密碼且貼入前已移除空格
  • Service Account JSON 沒有放入 ZIP、GitHub 或公開畫面
  • 六個變數完成後已執行 Redeploy
若不小心公開密鑰只刪檔案不夠；先撤銷或重新發行受影響密鑰，再更新 Vercel 並 Redeploy。公開過的密鑰視同已洩漏。
