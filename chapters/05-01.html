第 5 章｜部署 LINE Bot 至 Vercel

5-1 設定環境變數

下載 Python 正式學生版，以 Vercel Drop 建立 Project，再填入六個環境變數並 Redeploy。學生主線不經 GitHub。

進階篇8 分鐘提供完整範本

下載正式學生 ZIP查看範本說明開啟 Vercel Drop

一般學生不需要本機開發環境本流程不需要 Git、GitHub、Vercel CLI、Python、venv、pip、ngrok，也不需要在本機啟動 Flask。GitHub 只適合講師或後續長期維護，不是學生完成課程的必要條件。

用 Vercel Drop 建立 Project

  1. 下載正式學生 ZIP

    下載 LINE訊息整理Bot_課程正式版.zip。ZIP 根目錄直接包含 app.py、index.py、requirements.txt、vercel.json 與其餘正式 Python 檔案；不含真實 .env 或 Service Account JSON。

    下載正式學生 ZIP

  2. 登入 Vercel

    登入自己的 Vercel 帳號。課程只使用網頁操作。

  3. 開啟 Vercel Drop

    開啟官方 Drop 上傳頁；它接受 ZIP 或 folder，正式 ZIP 可以直接上傳，不用先解壓縮。

    開啟 Vercel Drop

  4. 拖入 ZIP 或資料夾

    直接拖入正式 ZIP；若你已經解壓縮，也可以拖入直接看得到 app.py 的專案資料夾。

  5. 等待 Project 建立

    等待 Vercel 建立 Project。第一次因尚未設定環境變數而失敗屬於預期情況；Project 建立後留在這個 Project 繼續設定。

不要重新 Drop ZIPVercel Drop 每次重新 Drop 都會建立新的 Project。正確順序是：第一次 Drop ZIP → 建立 Project → 設定六個 Environment Variables → Redeploy 原本 Project。環境變數填錯或更新時，也是在原 Project 修正後 Redeploy，不要再次 Drop。

填入六個環境變數

  1. 開啟 Environment Variables

    Vercel Project → Settings → Environment Variables，逐筆新增。Environment 至少勾選 Production。

  2. 貼入正式六個變數

    Name 大小寫必須完全一致；只有以下六個：

    環境變數名稱清單
    LINE_CHANNEL_SECRET
LINE_CHANNEL_ACCESS_TOKEN
GMAIL_ADDRESS
GMAIL_APP_PASSWORD
GOOGLE_SHEET_ID
GOOGLE_SERVICE_ACCOUNT_BASE64

    Vercel 的 Value 欄只貼真正的值。錯誤：LINE_CHANNEL_SECRET=abc123；正確：只貼 abc123。不要加雙引號、不要加單引號、不要帶變數名稱、不要帶前後空白，也不要多貼換行。

NameValue 來源
LINE_CHANNEL_SECRETLINE Developers Basic settings；前後不可有多餘空白
LINE_CHANNEL_ACCESS_TOKENMessaging API 的 Channel Access Token
GMAIL_ADDRESS完整寄件 Gmail 地址
GMAIL_APP_PASSWORD移除顯示用空格的 16 碼 App Password，不是一般登入密碼
GOOGLE_SHEET_IDSheets URL 的 /d/ 與 /edit 之間，不能填整條網址
GOOGLE_SERVICE_ACCOUNT_BASE64自己的 Service Account JSON 轉成的單行 Base64

在本頁產生並驗證 Base64

  1. 開啟 JSON 所在資料夾

    在檔案總管找到原始 Service Account JSON，確認實際檔名。在該資料夾空白處按右鍵 → 在終端機中開啟，或在位址列輸入 powershell 後按 Enter。

  2. 產生剪貼簿內容

    把 service-account.json 換成實際檔名後執行。沒有顯示大量文字是正常的，結果已複製到剪貼簿。

    Windows PowerShell｜產生
    [Convert]::ToBase64String([IO.File]::ReadAllBytes("service-account.json")) | Set-Clipboard

  3. 不洩密驗證

    執行以下兩行，只顯示 JSON 類型；正常輸出 service_account，不會印出憑證全文。

    Windows PowerShell｜驗證
    $b64 = Get-Clipboard
([Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($b64)) | ConvertFrom-Json).type
Base64 是編碼，不是加密Base64 和原始 JSON 同等敏感。禁止使用線上 Base64 converter，也不要貼到 GitHub、公開 ChatGPT 對話、教材、影片或截圖。

套用設定

  1. Redeploy

    六個環境變數儲存後，到原本 Project → Deployments → 選擇最新一筆 → Redeploy。只有重新部署後，Function 才會取得新設定；不要重新 Drop ZIP。

如何驗證成功

  • Vercel Project 已由 Drop 建立
  • Environment Variables 恰有六個正式名稱
  • GOOGLE_SHEET_ID 不是整條網址
  • GMAIL_APP_PASSWORD 不是一般登入密碼且貼入前已移除空格
  • Service Account JSON 沒有放入 ZIP、GitHub 或公開畫面
  • 六個變數完成後已執行 Redeploy
若不小心公開密鑰只刪檔案不夠；先撤銷或重新發行受影響密鑰，再更新 Vercel 並 Redeploy。公開過的密鑰視同已洩漏。
