第 4 章｜準備 LINE Bot 自動化環境

4-2 LINE Official Account 設定

從 LINE Official Account Manager 建立官方帳號並啟用 Messaging API；系統會建立對應 Channel，再到 Developers Console 取得兩個憑證並開啟群組加入權限。

進階篇5 分鐘現行 OA Manager 流程

開啟 Official Account Manager開啟 Developers Console

現行建立入口自 2024-09-04 起，Messaging API Channel 不能直接從 LINE Developers Console 新建。本課主流程一定從 LINE Official Account Manager → Settings → Messaging API → Use Messaging API 開始。

階段一：建立 LINE Official Account

  1. 開啟 Manager 並登入

    開啟 LINE Official Account Manager → 按 Log in／登入 → 選擇 LINE 帳號或 Business ID 的登入方式 → 完成驗證。若畫面要求同意條款，閱讀後按同意再繼續。

  2. 建立新的官方帳號

    在帳號清單按 Create new account／建立新帳號。在 Account name 輸入你希望顯示的 Bot 名稱，例如 工作紀錄測試 Bot；Email、Company/Business name、Country/Region、Business category 等必填欄位依你的真實資料選擇。課程未指定的圖片、狀態訊息與進階商務欄位可先維持預設或略過。

  3. 確認並建立

    按下一步／Continue → 在確認頁核對 Account name 與登入 Email → 按 Submit／Create。出現完成畫面後按 Go to LINE Official Account Manager 或開啟該帳號。

    你現在應該看到Manager 左上或帳號清單顯示剛建立的 Official Account，首頁可看到你設定的 Bot 名稱。若名稱不對，先回 Account settings 修正再往下。

階段二：啟用 Messaging API

  1. 開啟 Messaging API 設定

    進入剛建立的 Official Account → 右上角 Settings／設定 → 左側選單 Messaging API → 按 Use Messaging API。你需要這個帳號的管理員權限；沒有按鈕時先確認權限。

  2. 選擇或建立 Provider

    在 Provider 畫面選擇既有 Provider，或按建立新 Provider 並輸入名稱，例如你的個人／團隊名稱 → 按 Agree／同意或 Next → 在確認畫面按 OK。Provider 代表 Channel 的開發／營運主體，建立後不能任意移到另一個 Provider，請先選對。

  3. 等待系統建立 Channel

    回到 Messaging API 頁等待畫面完成。這一步由系統把目前 Official Account 連結成 Messaging API Channel；不需要到 Developers Console 再按建立。

    你現在應該看到Messaging API 頁顯示已啟用，並列出 Provider、Channel ID 或前往 Developers Console 的連結。這表示對應 Channel 已由系統建立。

階段三：取得 Channel Secret

  1. 登入 LINE Developers

    按 Messaging API 頁提供的 Developers 連結，或開啟 LINE Developers Console → 按 Log in，使用管理同一 Official Account 的帳號登入。第一次進入可能要求填 Developer name 與聯絡 Email；填入真實資料、同意條款後完成註冊。

    LINE Developers Console

  2. 開啟對應 Channel

    點選上一階段選定的 Provider → 在 Channels 清單找到與 Bot 名稱相同的 Messaging API Channel → 點進去。不要按建立新 Channel。

  3. 複製 Channel secret

    開啟 Basic settings 分頁 → 捲到 Channel secret → 按旁邊的複製按鈕。把它先存入本機安全的密碼管理器或暫存筆記，標記為 LINE_CHANNEL_SECRET；5-1 會貼到 Vercel Environment Variables。

    Secret 不要貼進聊天不要把 Channel secret 放入講義截圖、公開文件、GitHub、ChatGPT 對話或 LINE 群組。
    你現在應該看到Basic settings 顯示 Channel ID 與 Channel secret；你已把 secret 安全保存，並知道它之後放入 LINE_CHANNEL_SECRET。

階段四：發行 Token 並允許加入群組

  1. 發行 long-lived token

    在同一 Channel 點 Messaging API 分頁 → 捲到 Channel access token (long-lived) → 若尚未顯示 token，按 Issue → 確認發行；若已有 token，直接按複製。安全保存並標記為 LINE_CHANNEL_ACCESS_TOKEN，5-1 會貼到 Vercel。

    本課使用 long-lived token；不要改用 short-lived token，也不需要自行實作 v2.1 stateless token。重新發行 long-lived token 會讓舊的 long-lived token 失效，除非確定要輪替，否則不要按 Reissue。

  2. 允許 Bot 加入群組

    仍在 Messaging API 分頁 → 找到 Allow bot to join group chats → 選 Enabled。若介面使用開關，切到啟用狀態並依畫面儲存。

    LINE 群組限制一個 LINE 群組同一時間只能加入一個 LINE Official Account。若測試群組已有其他官方帳號，請先換一個測試群組或依團隊規範處理。
    你現在應該看到Channel access token (long-lived) 已有值，且 Allow bot to join group chats = Enabled。你已安全保存兩個 Vercel 會用到的值。

階段五：關閉本課不需要的預設回覆

  1. 調整回覆模式

    回到 LINE Official Account Manager → 開啟這個 Official Account → Settings／設定 → Response settings／回覆設定。將本課不需要的 Greeting message／加入好友歡迎訊息 與 Auto-response message／自動回覆訊息 關閉。若你的介面按回覆模式分組，保留 Messaging API 可用，避免 Manager 的預設回覆和 Python Bot 同時回答。

    Official Account Manager

  2. Webhook 先不要設定

    Developers Console 的 Messaging API → Webhook settings 目前先留空，Use webhook 也留到 5-2。你還沒有 Vercel Production Domain，現在無法組成正確的 /callback URL。

    你現在應該看到本課不需要的 Greeting／Auto-response 已關閉；Webhook URL 尚未設定。這是正確的中間狀態，不是漏做。

4-2 完成檢查

  • LINE Official Account 已建立，名稱正確
  • Messaging API 已從 Official Account Manager 啟用
  • Developers Console 的 Provider 下出現對應 Channel
  • Channel Secret 已取得並安全保存
  • Channel Access Token (long-lived) 已取得並安全保存
  • Allow bot to join group chats = Enabled
  • 本課不需要的 Greeting／Auto-response 已處理
  • Webhook 尚未設定，明確留到 5-2
