第 4 章｜準備 LINE Bot 自動化環境

4-3 Google Sheets 與 Gmail 設定

建立兩張工作表、Service Account 與 Gmail App Password。只建立正確表頭，不先填群組或假資料。

進階篇10 分鐘必要

新增 Google SheetGoogle Cloud ConsoleGoogle App Password

建立試算表

  1. 命名檔案

    新增空白試算表，左上角改名 LINE 訊息整理 Bot 紀錄。

    建立試算表

  2. 建立 groups 工作表

    將第一個分頁改名小寫 groups。把以下 Tab 分隔表頭貼到 A1，欄位順序不可交換。

    groups!A1:C1
    group_id	group_name	receiver_email

  3. 建立 messages 工作表

    按左下角 +，把第二個分頁改名小寫 messages。將以下 Tab 分隔表頭貼到 A1，欄位順序不可交換。

    messages!A1:H1
    webhook_event_id	message_id	group_id	user_id	display_name	message	created_at	sent

  4. 只保留表頭

    groups 與 messages 名稱必須完全小寫。現在不要建立群組資料列、不要填 group ID、不要放假資料。新的非重複一般群組文字會寫入 messages；它與相關群組控制指令都可能確保／更新 groups 的群組資料，但只有使用者輸入 #設定信箱 才會設定 receiver_email。

  5. 複製 Spreadsheet ID

    網址中 /d/ 與 /edit 之間的字串就是 GOOGLE_SHEET_ID。只複製這段，不要填整條網址。

建立 Service Account

  1. 建立／選擇 Cloud Project

    開啟 Google Cloud Console，頂端專案選單 → New Project → 輸入「LINE Project Memory」→ Create。

    建立 Cloud Project

  2. 啟用 Google Sheets API

    左上選單 → APIs & Services → Library → 搜尋 Google Sheets API → Enable。

  3. 新增 Service Account

    IAM & Admin → Service Accounts → Create service account。名稱輸入 line-sheet-writer。本課不需給整個 Cloud Project 額外角色。

  4. 下載 JSON Key

    進入服務帳號 → Keys → Add key → Create new key → 選 JSON → Create。

    Service Account JSON 是敏感憑證，不可上傳 GitHub、不可放進課程 ZIP，也不可出現在公開畫面或聊天中。

  5. 共用試算表

    打開 JSON，複製 client_email。回 Google Sheet 按 共用，貼上該 email，權限選 編輯者，取消通知後送出。

  6. 確認 JSON 實際檔名與完整路徑

    在檔案總管找到剛下載的 Service Account JSON，確認 JSON 的實際檔名與完整路徑。在檔案所在資料夾空白處按右鍵 → 在終端機中開啟，或在位址列輸入 powershell 後按 Enter。

  7. 轉成 Base64 並立即貼入 Vercel

    把下列 完整JSON路徑 換成你的實際完整路徑後執行：

    Windows PowerShell｜產生並複製
    [Convert]::ToBase64String([IO.File]::ReadAllBytes("完整JSON路徑")) | Set-Clipboard

    PowerShell 沒有顯示大量文字是正常的，因為結果已直接複製到剪貼簿。

    立即前往 Vercel，把剪貼簿內容貼入 GOOGLE_SERVICE_ACCOUNT_BASE64 的 Value。如果 Vercel Project 尚未建立，直接進入下一節 5-1；完成第一次 Drop 建立 Project 後，回到 PowerShell 重新執行這個指令再貼入。

    貼入 Vercel 前不要再複製其他文字，否則剪貼簿內容會被覆蓋；若已被覆蓋，重新執行 PowerShell 指令即可。

    可以自行切換 Vercel Value 的顯示／遮蔽狀態，確認已貼入一整串很長的 Base64 字串，但這不代表 Base64 有效性的技術驗證。最終是否設定正確，以部署與實際 Google Sheets 寫入測試為準。

Base64 是編碼，不是加密GOOGLE_SERVICE_ACCOUNT_BASE64 與原始 Service Account JSON 同等敏感。不可公開、不可提交 GitHub、不可貼到公開聊天或任何線上 Base64 converter，也不可放進教材、影片或截圖。

建立 Gmail App Password

  1. 開啟兩步驟驗證

    Google Account → Security／安全性 → 2-Step Verification／兩步驟驗證，依指示完成。即使已開啟仍找不到 App Password，常見原因是 Security Key-only 兩步驟驗證、公司／學校組織管理帳號限制，或已啟用 Advanced Protection。

  2. 新增 App Password

    打開 App Password 頁面，再次驗證身分；名稱輸入「LINE Project Memory」，按 Create／建立。

    建立 App Password

  3. 安全保存

    GMAIL_ADDRESS 必須是建立這組 App Password 的寄件 Google 帳號。GMAIL_APP_PASSWORD 不是 Gmail 一般登入密碼；Google 顯示的 16 碼 App Password 貼入前必須移除顯示用空格。若之後修改一般登入密碼，既有 App Password 可能被撤銷，需重新建立並更新 Vercel。

如何驗證成功

  • 第一張是 groups、第二張是 messages，名稱完全小寫且欄位順序一致
  • 兩張表只有正確表頭，沒有手動群組列或假資料
  • Google Sheets API 顯示 Enabled
  • Service Account 的 client_email 是試算表編輯者
  • 已安全取得 GOOGLE_SHEET_ID、GOOGLE_SERVICE_ACCOUNT_BASE64 與無空格的 Gmail App Password
