第 5 章｜部署 LINE Bot 至 Vercel

5-2 部署、Webhook 與驗證

確認 Python Deployment 為 Ready，把 Production Domain 加上 /callback 設為 LINE Webhook，再用三個正式指令與一般文字驗證。

進階篇12 分鐘完整串接

完成 Vercel 部署

  1. Redeploy

    確認六個 Environment Variables 都已儲存，到 Project → Deployments → 最新一筆 → Redeploy。

    開啟 Vercel

  2. 確認 Deployment Ready

    等待最新 Deployment 顯示 Ready。目前程式沒有 GET / health page，因此瀏覽器直接開啟 https://你的網域/ 看到 404，不代表 Bot 部署失敗；LINE 會對 /callback 發送有簽章的 POST Webhook。

  3. 複製穩定 Production Domain

    到 Project 的 Domains 複製穩定 Production Domain，例如 https://line-project-memory-bot.vercel.app。不要使用每次 Deployment 產生的 Preview／Deployment URL 作為正式 Webhook。

  4. 需要時查看 Logs

    若部署 Ready 但後續失敗，打開最新 Deployment 的 Logs／Deployment Logs，查看最新 Function 錯誤，再修正 Environment Variables 並 Redeploy。

設定 LINE Webhook

  1. 組合 Webhook URL

    正式 Webhook 路徑固定為 /callback：

    替換成你的 Production Domain
    https://你的-project.vercel.app/callback

  2. 貼入 LINE Developers

    回 Channel → Messaging API → Webhook settings → Edit，貼上完整網址並儲存。

    LINE Developers Console

  3. Verify 並啟用 Webhook

    按 Verify，成功應顯示 Success；再將 Use webhook 設為 Enabled。

  4. 確認允許加入群組

    確認 Allow bot to join group chats 已設為 Enabled。

測試順序

  1. 把 Bot 加入測試群組

    使用 Messaging API 頁面的 QR code 加官方帳號好友，再把 Bot 邀入測試群組。加入時的 join 會觸發歡迎訊息，但不會寫入 messages。

  2. 設定群組收件信箱

    在群組輸入下列格式，將 placeholder 換成實際可收信地址；使用半形 #，指令後輸入一個一般半形空格：

    替換成自己的實際收件信箱
    #設定信箱 <你的實際 Email>

    Bot 應回覆已設定目前群組的紀錄收件信箱；這個控制指令會建立／更新 groups 並設定 receiver_email，但不寫入 messages。

  3. 查看群組收件信箱

    輸入 #查看信箱，確認 Bot 回覆剛才設定的地址。

  4. 送出一般文字

    輸入「測試專案：第一版 10/20 完成」。只有這則新的非重複群組文字應寫入 messages；它也可能確保／更新目前群組的 groups 資料，但不會自行設定 receiver_email。三個控制指令都不會寫入 messages。

  5. 檢查 groups 與 messages

    groups 應有目前群組的 group_id、group_name、receiver_email；messages 應出現一般訊息，且新訊息的 sent 是 FALSE。

如何驗證成功

  • 六個環境變數填完後已 Redeploy，Deployment 顯示 Ready
  • Webhook URL 使用穩定 Production Domain、是 HTTPS 且以 /callback 結尾
  • LINE Developers Verify 顯示 Success，Use webhook 已開啟
  • Allow bot to join group chats 已開啟
  • #設定信箱 與 #查看信箱 有正確回覆
  • groups 已出現群組與收件信箱
  • 群組新文字成功寫入 messages，控制指令沒有寫入，新訊息 sent = FALSE
正式判定方式以 Deployment 顯示 Ready、LINE Verify 顯示 Success、群組新文字成功寫入 Sheets 三項為準；根網址 404 不是失敗證據。修改變數後一定要 Redeploy。
