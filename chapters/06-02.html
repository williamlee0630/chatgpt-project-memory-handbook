6-2 完整測試與跨來源週期排程

先手動跑完 Google Drive 會議逐字稿 + Gmail [LINE紀錄] 的跨來源驗證；兩邊都成功後，最後才建立週期排程。

進階篇10 分鐘Drive + Gmail 已實測成功

開啟 Google Drive開啟 Gmail開啟 ChatGPT

先手動驗證成功，再自動化只看到 Connected、Deployment Ready 或郵件主旨都不夠。你要先在專案主對話證明 ChatGPT 能實際讀取 Drive 完整逐字稿與 Gmail 正文，並正確判斷版本變更，才進入本頁最後的 Scheduled Task。
本節使用虛構練習案例以下「活動籌備專案」只用來練習版本變更、負責人延續與候選日期判斷，不代表任何真實專案紀錄。

第一階段：手動端到端測試

  1. 準備會議當下版本

    前往 Google Meet 建立測試會議 → 讓 Tactiq 記錄：「活動籌備專案的場地確認由活動窗口負責，4/18 完成。公開報名日尚未決定。」→ 正常結束會議 → 到 Tactiq My Meetings 確認完整 Transcript → 等待 Automatic Workflow 寫入 Google Drive 的「會議原始紀錄」。

  2. 確認 Drive 文件

    開啟 Google Drive → 會議原始紀錄 → 點開剛產生的 Google Docs → 搜尋「4/18」，確認正文真的有練習案例，不是只有文件名稱。

    你現在應該看到Google Docs 有完整逐字稿，且能找到「活動籌備專案」「活動窗口」「4/18」「公開報名日尚未決定」。

  3. 準備 LINE 會後更新

    在對應測試 LINE 群組輸入：「活動籌備專案的場地確認期限改為 4/21，負責人仍為活動窗口。」再輸入：「4/25 可以作為候選公開報名日。」→ 輸入 #寄出紀錄 → 等 Bot 回覆寄送完成。

  4. 確認 Gmail 與 Sheets

    開啟 Gmail → 重新整理 → 找到主旨 [LINE紀錄][群組名稱] 日期 → 點開正文，確認有兩句對話。再到 Google Sheet 的 messages 核對兩列 group_id 屬於目前群組、message 保留原文，寄送後 sent = TRUE。

    你現在應該看到Gmail 正文有兩句 LINE 更新；Sheets 對應兩列為 TRUE。若 Email 未出現，先停在 LINE → Gmail 路徑排錯，不要進入 ChatGPT。

  5. 回到同一個專案主對話

    開啟 ChatGPT 網頁版 → 左側欄的 Projects／專案 → 工作訊息整理 → 開啟目前「活動籌備專案」的主對話，不要建立新聊天。確認 Google Drive 與 Gmail 可由 Plugins／Apps（依目前介面顯示名稱為準） 使用 → 貼上 Prompt 2 的「後續更新簡短版」，指定本次測試日期並要求重新取得兩邊資料。

    開啟 Prompt 2

  6. 核對判斷與來源

    答案應列出決策變更 4/18 → 4/21；負責人仍是活動窗口；4/25 只能列在未決／候選，不得列為已確認公開報名日。最後必須列出實際讀取的 Google Drive 文件與 Gmail 郵件，並排除其他專案。任一來源無法存取時，答案必須明確說明，不能假裝完成。

    你現在應該看到同一則回答同時引用 Drive 完整逐字稿與 Gmail [LINE紀錄] 正文，專案歸屬與版本判斷正確，且列出需要人工確認的事項。到這裡才算手動跨來源驗證成功。

第二階段：建立跨來源週期排程

Google Drive + Gmail [LINE紀錄] → ChatGPT → 跨來源工作記憶

  1. 再次確認排程前提

    Drive 已有可讀取的會議完整逐字稿、Gmail 已有可讀取的 [LINE紀錄]，而且上一階段的專案主對話能實際讀取兩邊。任一項未完成就先回去排錯。

  2. 在網頁版開啟 Scheduled

    開啟 ChatGPT 網頁版，在左側欄點 Scheduled／排程。本課排程步驟全部以網頁版為準，不需要切換到 Windows App。若側欄沒有這個入口，可能是你的帳號、plan、region、workspace、管理員政策或目前介面版本尚未提供；這不代表你操作錯誤，也不要改在 Codex 建立。

  3. 建立新排程

    在 Scheduled 頁按建立新任務，或選 Try your own（實際名稱可能隨介面版本調整）→ 貼上下方 Prompt 3 → 把 ＿＿＿＿專案 換成要持續追蹤的實際專案名稱 → 設定每天、每週或你需要的頻率與時間 → 核對時區 → 儲存。若系統先建立對話再讓你設定時間，依確認卡或時鐘按鈕完成排程。

  4. 確認排程管理入口

    建立後可回到左側欄的 Scheduled／排程 查看、編輯、暫停或刪除任務。另一條網頁版路徑是 Settings／設定 → Notifications／通知 → Manage tasks／管理任務；從個別任務對話的更多選單也可能看到 See scheduled tasks／查看排程任務。

  1. 確認 Plugins／Apps 權限

    在 ChatGPT 網頁版開啟 Settings／設定 → Plugins／Apps，確認 Google Drive 與 Gmail 已連接；若排程關聯對話提供 +／工具選單，也要確認這兩個來源可選用。排程能否使用來源取決於你的 account、plan、region、workspace 權限、管理員政策與當下可用的 Plugins／Apps；一般對話能使用，不代表每個排程環境都必然能用。

  2. 檢查第一次執行

    等待第一次排程執行，或若介面提供立即執行／測試就執行一次 → 打開結果 → 核對指定專案、實際時間範圍、Drive 文件、Gmail 郵件、已確認決策、待辦、變更與排除資料。若只讀到一邊，或混入其他專案，這次不能算完整跨來源更新。若指定結束日晚於執行日，後段尚未發生，不得寫成查無資料。

    你現在應該看到Scheduled 頁列出任務名稱、下一次執行時間與頻率；第一次結果清楚區分「已讀取且找到相關資料」「指定已發生期間內未找到相關資料」「目前無法存取此來源」與「該期間尚未發生」。有新資料時只更新指定專案，沒有新資料時明確說「本次週期沒有新的工作記憶需要更新」。
排程限制：Project 不是來源存取保證不能只因排程建立在 Project 裡，就假設每次執行一定能讀取 Project 上傳檔案或 Project sources。每次執行都要依 Prompt 重新搜尋已連接的 Google Drive 與 Gmail，實際開啟逐字稿與郵件正文，並列出本次讀到的來源。可用性仍受帳號、plan、region、workspace、管理員政策與目前 Plugins／Apps 能力影響；本課也不承諾結果會自動寫回 Project。若排程不能存取任一來源，回到專案主對話手動執行 Prompt 2，不要宣稱已完成完整跨來源整理。

失敗時怎麼查

不要一次重設所有帳號。先記下最後一個成功節點，再到排錯中心依 A～J 情境檢查 Base64、Sheets 權限、Gmail SMTP、Vercel、LINE 與 ChatGPT 來源。

開啟 A～J 排錯情境

常見限制

  • Bot 只能取得加入後的新文字訊息，不會補抓歷史。
  • 本範本主線處理文字；圖片、貼圖、檔案與語音需另行設計。
  • 刪除或收回 LINE 訊息不一定能同步移除已保存紀錄。
  • 免費額度、App Password、LINE／Vercel／Tactiq／ChatGPT 政策可能調整，以官方當下頁面為準。
  • Automatic Workflow 可能延遲；手動 Run 是備援，但太早執行可能重複。
