最後一集依序完成 Google Drive + Gmail 跨來源驗收、Skill 成果展示、週期排程與課程總驗收。詳細安裝步驟集中在 Skill Kit 附錄。

開啟 Google Drive開啟 GmailChatGPT Web 備用入口

先手動驗證成功，再自動化只看到 Connected、Deployment Ready 或郵件主旨都不夠。你要先在專案主對話證明 ChatGPT 能實際讀取 Drive 完整逐字稿與 Gmail 正文，並正確判斷版本變更，才進入本頁最後的 Scheduled Task。
本節使用兩組匿名化錄影案例主要示範分別取自 2026-10-06「活動籌備專案」與 2026-10-17「研討會討論專案」的 LINE Bot Gmail 郵件；下載檔依實際課程測試紀錄改寫。兩封郵件都不是 Drive 會議逐字稿，兩個專案也必須分開整理。

第一階段：Google Drive + Gmail 跨來源完整驗收

先分清來源與專案這次兩組主要案例都來自 Gmail 中的 LINE Bot 郵件。先核對各封郵件正文，再逐案尋找屬於同一專案的 Google Drive／Tactiq 會議資料；只有 LINE 郵件時，可完成 LINE 整理與 Skill 練習，不能宣稱該專案已完成 Drive + Gmail 跨來源驗收。

  1. 核對兩封 Gmail 正文

    在 Gmail 找到 2026-10-06 活動籌備與 2026-10-17 研討會討論的 [LINE紀錄] 郵件，實際打開正文核對訊息時間與專案歸屬；公開練習可下載活動籌備匿名化 LINE 紀錄及研討會討論匿名化 LINE 紀錄。這兩份 TXT 只代表 LINE／Gmail 來源。

    活動籌備：10/6 郵件內明確說明場地期限 10/18 改成 10/12、原負責人維持不變、報名頁預計 10/15 前完成，主持人確認 10/16 上午 10 點開放報名的計畫安排。研討會討論：10/17 郵件只把下次討論日期暫定為 10/31，沒有具體時間或個人期限。

  2. 保留 LINE Bot、Sheets、Gmail 路徑驗收

    實作自己的 LINE 測試時，在對應群組輸入文字與 #寄出紀錄，等 Bot 回覆後開啟 Gmail 郵件正文；到 Google Sheet 的 messages 核對 group_id 僅屬目前群組、message 保留原文、寄送後 sent = TRUE。公開教材只記錄匿名角色，不貼出真實識別碼或郵件地址。

  3. 確認 Tactiq → Google Drive 會議來源

    保留原有操作：Google Meet 結束後，先在 Tactiq My Meetings 檢查完整 Transcript 與 Automatic Workflow，再到 Google Drive 的「會議原始紀錄」打開 Google Docs 正文。核對文件的專案、會議發生日期、實際語句及來源連結；檔名或搜尋結果不足以證明已讀到正文。若本次沒有讀到確定屬於該專案的 Drive 文件，就標示「Drive 來源待補」，不要補寫會議內容。

  4. 辨識來源差異並人工確認

    已知 2026-10-03 活動籌備 Tactiq 逐字稿曾辨識出「4 月 18 日」，而 10/6 LINE 郵件說的是「10/18 改成 10/12」。10/18 → 10/12 只由 10/6 LINE 郵件本身支持；不能寫成 10/3 會議的「4/18」直接改成「10/12」。若比較兩個來源，應列出原句、日期差異與需要人工確認。研討會討論若沒有同專案 Drive 文件，也同樣保留待驗收狀態。

  5. 回到各自專案的主對話驗收

    在 ChatGPT Desktop App 的對應 Project 工作記憶對話，確認 Google Drive 與 Gmail 的 Plugins／Apps 可用，再用Prompt 2 後續更新簡短版指定單一專案、紀錄期間與允許來源，要求重新讀取正文。只有實際讀到同一專案的 Drive 會議文件和 Gmail LINE 郵件，並正確列出決策、衝突與來源，才可勾選跨來源驗收成功；否則如實記錄已讀來源與缺口。

只使用已安裝的單一 project-work-assistant Skill。四種服務、安裝驗收及互動式提問維持原樣。啟動後選「3. 更新最新專案工作記憶」，回答缺少的專案、日期範圍與資料來源；不必重新貼長篇 Prompt。Codex 若讀不到 ChatGPT Project 的連接來源，就提供下方可讀的匿名化 TXT。

  1. 沿用原有安裝與驗收流程

    需要安裝時，開啟一鍵安裝教學並下載專案工作助理 ZIP；已安裝且驗收成功者直接啟動。Skill 本體與 ZIP 不因教材案例更新而改動。

  1. 再次啟動原 Skill 或在對話中明確切換專案，選 3，指定「研討會討論專案」、2026-10-17 的來源紀錄與研討會練習檔。切換後須重新確認來源與期間。
  2. 核對工作記憶：下一次討論日期暫定 2026-10-31，不能列為正式確認；具體時間未確認。成員只被建議先準備各自內容，沒有具體分派的個人工作或期限。結果不得出現活動籌備的場地、報名頁和日期。
分開工作記憶與跨來源狀態兩份下載檔可驗證 LINE 決策、待辦、暫定與專案隔離，但不能代表 Drive + Gmail 雙來源都已讀取。10/3 逐字稿的「4 月 18 日」與 10/6 郵件的「10/18」若一起使用，先列差異待人工確認。舊版 01_meeting.txt、02_line_email.txt 留作進階虛構練習，不是本節錄影案例。

同專案設定可在你同意後，保存非敏感的專案名稱、來源參照、時區與已驗收的成功截止日；不同專案分開保存。更新失敗不能推進截止日。若無寫入權限，只沿用目前對話確實可確認的資訊。完整的互動示範、設定保存與切換專案說明在附錄。需要週報時仍可選服務 4；沒有 Skill 功能時，可用四份 Prompt 相容版。

第三階段：設定跨來源週期排程

Google Drive + Gmail [LINE紀錄] → ChatGPT → 跨來源工作記憶

確認排程設定介面建立排程時，Prompt 必須明確描述排程意圖與執行頻率。如果只要求「更新工作記憶」，ChatGPT 可能將它視為一般的一次性任務。貼上本教材 Prompt 後，請確認畫面有出現「重複／每天／時間」等排程設定，本課示範設定為每天 15:00、時區 Asia/Taipei 後儲存。介面名稱與呈現方式可能隨版本調整。

  1. 再次確認排程前提

    Drive 已有可讀取的會議完整逐字稿、Gmail 已有可讀取的 [LINE紀錄]，而且第一階段的專案主對話能實際讀取同專案兩邊正文。任一項未完成就先回去排錯。

  2. 在 Desktop App 開啟 Scheduled

    在 ChatGPT Desktop App 找到 Scheduled／排程 入口並開啟。若目前介面沒有此入口，可用相同帳號從 ChatGPT Web 備用入口查看；不同版本的入口位置與名稱請依目前介面為準。若兩邊都沒有，可能是帳號、plan、region、workspace、管理員政策或目前介面版本尚未提供；這不代表你操作錯誤，也不要改在 Codex 建立。

  3. 建立新排程

    在 Scheduled 頁按建立新任務，或選 Try your own（實際名稱可能隨介面版本調整）→ 貼上下方 Prompt 3 → 把 ＿＿＿＿專案 換成要持續追蹤的實際專案名稱 → 確認排程設定顯示重複、本課示範的每天 15:00 與 Asia/Taipei → 儲存；實際使用可自行調整時間與頻率。若系統先建立對話再讓你設定時間，依確認卡或時鐘按鈕完成排程。

  4. 依需求設定任務通知

    儲存排程後，到 ChatGPT → 設定 → 通知 → 任務，依需求開啟推播、電子郵件或兩者。Prompt 負責定義任務要做什麼；Email／Push 屬於 ChatGPT 帳號層級的通知設定。兩者不是同一件事，可用的通知管道也可能依帳號、裝置與目前介面而異。

    通知不是 Prompt 控制A. Gmail Connector：用來讀取 [LINE紀錄] 等工作來源。
    B. ChatGPT Task Email Notification：由 ChatGPT 系統通知某次排程任務已有更新／結果。這不是透過課程中的 Gmail Connector 主動寄信，也不可因為 Prompt 寫了「通知」就假設 Email 或 Push 一定送達。

  5. 確認排程管理入口

    建立後可回到左側欄的 Scheduled／排程 查看、編輯、暫停或刪除任務。若使用 ChatGPT Web 備用入口，另一條可能的路徑是 Settings／設定 → Notifications／通知 → Manage tasks／管理任務；從個別任務對話的更多選單也可能看到 See scheduled tasks／查看排程任務。

這是課程示範設定，不代表每個人都必須選擇下午三點。實際使用時，可以按照自己的工作習慣調整執行時間與頻率；若改動，Prompt 3 的週期與資料時間窗也要同步調整並重新核對。實際執行時間由排程設定控制；資料日期範圍由任務提示詞和來源紀錄決定，不要混為一談。

建立後驗證

排程建立完成不等於已驗收。排程與 Skill 是不同功能；安裝 Codex Skill 不會自動讓這個 ChatGPT 排程使用它。請分開確認排程有執行、指定來源有讀取、結果判斷正確、通知有送達四個層級。

  1. 確認下一次執行時間

    回到排程／任務頁，確認任務顯示正確的下一次執行時間，並確認任務處於啟用狀態。

  2. 確認時區與執行時間

    核對排程使用的時區與預定時間。本課示範每天 15:00、Asia/Taipei；若你選擇其他時間或時區，以自己儲存的排程為準，核對帳號或裝置顯示是否一致。

  3. 再次確認通知設定

    到 設定 → 通知 → 任務，確認需要的推播與電子郵件已開啟。這只設定通知管道，不會改變 Prompt，也不會替代任務執行結果。

  4. 確認 Plugins／Apps 權限

    在 ChatGPT Desktop App 開啟 Settings／設定 → Plugins／Apps（依目前介面顯示名稱為準），確認 Google Drive 與 Gmail 已連接；若使用 ChatGPT Web 備用入口，也在該介面確認連線狀態。若排程關聯對話提供 +／工具選單，也要確認這兩個來源可選用。排程能否使用來源取決於你的 account、plan、region、workspace 權限、管理員政策與當下可用的 Plugins／Apps；一般對話能使用，不代表每個排程環境都必然能用。

  5. 檢查第一次執行

    第一次排程執行後，不要只看 Email。先回到 ChatGPT 的排程／任務頁，確認任務是否真的有執行、是否有新的執行結果，再打開結果核對指定專案、實際時間範圍、Drive 文件、Gmail 郵件、已確認決策、待辦、變更與排除資料。若只讀到一邊，或混入其他專案，這次不能算完整跨來源更新。若指定結束日晚於執行日，後段尚未發生，不得寫成查無資料。

    你現在應該看到Scheduled 頁列出任務名稱、下一次執行時間與頻率；第一次結果清楚區分「已讀取且找到相關資料」「指定已發生期間內未找到相關資料」「目前無法存取此來源」與「該期間尚未發生」。有新資料時只更新指定專案，沒有新資料時明確說「本次週期沒有新的工作記憶需要更新」。

  6. 再確認下一個週期

    如果是每天、每週等重複排程，不要因為第一次成功就判定設定完成。至少再確認下一個週期是否真的再次執行。

判斷問題的順序
  1. 第一層：排程有沒有實際執行？
  2. 第二層：指定 Drive／Gmail 來源有沒有實際讀取？
  3. 第三層：結果的專案、日期、決策與待辦是否正確？
  4. 第四層：Email／Push 有沒有送達？
排程執行、資料讀取、結果正確與通知配送是四個不同層級；沒有收到 Email，不能直接判定排程失敗。
重要：第一次通知不是長期保證第一次收到 Task Update，不代表重複排程之後每次都一定會正常執行。建立 Daily／Weekly 重複任務後，至少要確認第一次執行成功，並再檢查下一次週期仍有執行；不要把第一次 Email 當成唯一驗收條件。

第四階段：最終成果驗收與課程總結

用兩組錄影案例逐項核對。來源缺少或衝突時保持未驗收狀態；任何「已完成」都需要後續完成證據。

  1. 活動籌備 10/6 Gmail／LINE 正文實際可讀；工作記憶以該郵件支持 10/18 → 10/12，原負責人維持，報名頁預計 10/15 前完成，場地與報名頁均不擅自標完成。
  2. 活動籌備的 10/16 上午 10 點公開報名已由主持人確認為計畫安排，並註明場地確認為前置條件；活動主視覺列未決。
  3. 研討會討論 10/17 Gmail／LINE 正文實際可讀；10/31 只列暫定日期，沒有具體時間、個人分派或期限。
  4. 兩個專案的工作記憶互相隔離；結果列出各自實際讀取的來源，不混入其他專案。
  5. 10/3 Tactiq 的「4 月 18 日」與 10/6 LINE 的「10/18」如需跨來源比較，列為來源差異與人工確認，不能製造連續決策。
  6. 逐案打開同專案 Drive／Tactiq 文件與 Gmail 郵件正文後，才標記 Google Drive + Gmail 跨來源驗收成功；缺一邊就標示待補。
  7. 原有 Skill 的四種服務、互動式提問、啟動指令與 ZIP 下載仍可用；週報有日期範圍及來源。
  8. ChatGPT 週期排程的時間、首次與下一週期執行結果已核對；排程、來源讀取、結果與 Email／Push 通知分開驗收。
課程總結你已練習用 LINE 紀錄整理決策與未決事項，並用單一互動式 Skill 分別更新兩個專案。Google Meet → Tactiq → Drive 與 LINE → Bot → Sheets → Gmail 的跨來源驗收，仍以各專案實際讀到的正文與人工核對結果為準。
完成課程後，ChatGPT 可以成為你的日常工作助手你已學會保存會議逐字稿與 LINE 工作紀錄，並用 ChatGPT 整理跨來源工作記憶。只要本次需要的資料確實可讀，就可以依工作需求查待辦、整理進度、比較決策、產生報告或指定不同輸出格式；講義的 Prompt 與 Skill 是提高效率的工具，不是唯一用法。不必記住每一段提示詞；重要的是知道資料在哪裡、如何讓 ChatGPT 正確讀取，以及如何判斷整理結果是否可信。
