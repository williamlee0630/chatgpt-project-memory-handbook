6-2 完整測試與跨來源週期排程

先手動跑完 Google Drive 會議逐字稿 + Gmail [LINE紀錄] 的跨來源驗證；兩邊都成功後，最後才建立週期排程。

進階篇10 分鐘Drive + Gmail 已實測成功

開啟 Google Drive開啟 Gmail開啟 ChatGPT

先手動驗證成功，再自動化只看到 Connected、Deployment Ready 或郵件主旨都不夠。你要先在專案主對話證明 ChatGPT 能實際讀取 Drive 完整逐字稿與 Gmail 正文，並正確判斷版本變更，才進入本頁最後的 Scheduled Task。

第一階段：手動端到端測試

  1. 準備會議當下版本

    前往 Google Meet 建立測試會議 → 讓 Tactiq 記錄：「第一版由小美負責，10/20 完成。上架日尚未決定。」→ 正常結束會議 → 到 Tactiq My Meetings 確認完整 Transcript → 等待 Automatic Workflow 寫入 Google Drive 的「會議原始紀錄」。

  2. 確認 Drive 文件

    開啟 Google Drive → 會議原始紀錄 → 點開剛產生的 Google Docs → 搜尋「10/20」，確認正文真的有測試句，不是只有文件名稱。

    你現在應該看到Google Docs 有完整逐字稿，且能找到「小美」「10/20」「上架日尚未決定」。

  3. 準備 LINE 會後更新

    在對應測試 LINE 群組輸入：「第一版期限改為 10/23，小美負責不變。」再輸入：「10/30 可以當候選上架日。」→ 輸入 #寄出紀錄 → 等 Bot 回覆寄送完成。

  4. 確認 Gmail 與 Sheets

    開啟 Gmail → 重新整理 → 找到主旨 [LINE紀錄][群組名稱] 日期 → 點開正文，確認有兩句對話。再到 Google Sheet 的 messages 核對兩列 group_id 屬於目前群組、message 保留原文，寄送後 sent = TRUE。

    你現在應該看到Gmail 正文有兩句 LINE 更新；Sheets 對應兩列為 TRUE。若 Email 未出現，先停在 LINE → Gmail 路徑排錯，不要進入 ChatGPT。

  5. 回到同一個專案主對話

    ChatGPT 左側欄 → 專案工作記憶 → 開啟 3-1 的專案主對話，不要建立新聊天。確認 Google Drive 與 Gmail Apps 仍連接 → 使用 Prompt 2 的「後續更新簡短版」指定本次測試日期，要求重新取得兩邊資料。

    開啟 Prompt 2

  6. 核對判斷與來源

    答案應列出決策變更 10/20 → 10/23；小美仍是負責人；10/30 只能在未決／候選，不得列為已確認上架日。最後必須列出實際讀取的 Google Drive 文件與 Gmail 郵件。任一來源無法存取時，答案必須明確說明，不能假裝完成。

    你現在應該看到同一則回答同時引用 Drive 完整逐字稿與 Gmail [LINE紀錄] 正文，版本判斷正確，且列出需要人工確認的事項。到這裡才算手動跨來源驗證成功。

第二階段：建立跨來源週期排程

Google Drive + Gmail [LINE紀錄] → ChatGPT → 跨來源工作記憶

  1. 再次確認排程前提

    Drive 已有可讀取的會議完整逐字稿、Gmail 已有可讀取的 [LINE紀錄]，而且上一階段的專案主對話能實際讀取兩邊。任一項未完成就先回去排錯。

  2. 開啟 Scheduled

    在 ChatGPT 網頁版左側欄點 Scheduled／排程。若側欄沒有這個入口，代表你的帳號、方案、app 版本或工作區目前未提供；不要虛構按鈕，也不要改在 Codex 建立。你也可從 Settings → Notifications → Manage tasks 查看已存在的任務。

  3. 建立新排程

    在 Scheduled 頁按建立新任務，或選 Try your own（實際名稱可能隨介面版本調整）→ 貼上下方 Prompt 3 → 設定每天、每週或你需要的頻率與時間 → 核對時區 → 儲存。若系統先建立對話再讓你設定時間，依確認卡或時鐘按鈕完成排程。

  1. 確認 Apps 權限

    在排程關聯對話或 Apps 頁確認 Google Drive 與 Gmail 已連接。排程能否使用來源取決於你的 account、plan、region、workspace 權限、管理員政策與當下可用的 App／Plugin；一般對話能使用，不代表每個排程環境都必然能用。

  2. 檢查第一次執行

    等待第一次排程執行，或若介面提供立即執行／測試就執行一次 → 打開結果 → 核對實際時間範圍、Drive 文件、Gmail 郵件、已確認決策、待辦、變更與排除資料。若只讀到一邊，這次不能算完整跨來源更新。

    你現在應該看到Scheduled 頁列出任務名稱、下一次執行時間與頻率；第一次結果清楚區分「成功存取但查無符合資料」與「無法存取」。有新資料時列出兩類來源，沒有新資料時明確說「本次週期沒有新的工作記憶需要更新」。
排程限制：不要依賴 Project 檔案ChatGPT 官方目前明確說明：若在含檔案的 Project 中建立 Scheduled Task，任務不能存取該 Project 中上傳或保存的檔案。因此本課排程只以已連接的 Google Drive + Gmail 為主要來源，也不承諾把結果自動寫回 Project。若排程不能存取任一來源，回到專案主對話手動執行 Prompt 2；不要宣稱所有帳號都一定能自動跨來源整理。

失敗時怎麼查

不要一次重設所有帳號。先記下最後一個成功節點，再到排錯中心依 A～J 情境檢查 Base64、Sheets 權限、Gmail SMTP、Vercel、LINE 與 ChatGPT 來源。

開啟 A～J 排錯情境

常見限制

  • Bot 只能取得加入後的新文字訊息，不會補抓歷史。
  • 本範本主線處理文字；圖片、貼圖、檔案與語音需另行設計。
  • 刪除或收回 LINE 訊息不一定能同步移除已保存紀錄。
  • 免費額度、App Password、LINE／Vercel／Tactiq／ChatGPT 政策可能調整，以官方當下頁面為準。
  • Automatic Workflow 可能延遲；手動 Run 是備援，但太早執行可能重複。
