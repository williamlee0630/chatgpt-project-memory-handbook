開啟 Google Drive開啟 GmailChatGPT Web 備用入口

先手動驗證成功，再自動化只看到 Connected、Deployment Ready 或郵件主旨都不夠。你要先在專案主對話證明 ChatGPT 能實際讀取 Drive 完整逐字稿與 Gmail 正文，並正確判斷版本變更，才進入本頁最後的 Scheduled Task。
本節使用虛構練習案例以下「活動籌備專案」只用來練習版本變更、負責人延續與候選日期判斷，不代表任何真實專案紀錄。

第一階段：Google Drive + Gmail 跨來源完整驗收

先選擇你的練習資料使用講義下載的虛構練習檔：會議紀錄是 2026-04-16、LINE 紀錄是 2026-04-17；場地原期限 2026-04-18、新期限 2026-04-21，2026-04-25 是尚未定案的候選公開報名日。這組固定日期只用於下載檔與下方預期答案；可直接到第二階段的本機檔案 Skill 練習。
自行建立 Google Meet 與 LINE 紀錄：依下列步驟驗收 Drive／Gmail，使用實際練習當天的紀錄日期，自行設定合理且彼此一致的原期限、新期限和候選日期，不要照抄講義日期。

  1. 準備會議當下版本

    前往 Google Meet 建立測試會議，讓 Tactiq 記錄：「活動籌備專案的場地確認由活動窗口負責，原訂在【自訂原期限】完成。公開報名日期尚未確定。」請填入實際合理的原期限。若使用下載的虛構練習檔，原文中的期限仍是 2026-04-18。正常結束會議後，到 Tactiq My Meetings 確認完整 Transcript，等待 Automatic Workflow 寫入 Google Drive 的「會議原始紀錄」。

  2. 確認 Drive 文件

    開啟 Google Drive → 會議原始紀錄 → 點開剛產生的 Google Docs，搜尋你實際說出的「活動籌備專案」和原期限，確認正文真的有內容，不只看文件名稱。使用下載檔才核對固定的 2026-04-18。

    你現在應該看到Google Docs 有完整逐字稿、專案名稱、活動窗口與實際說出的原期限；公開報名日尚未決定。

  3. 準備 LINE 會後更新

    在對應測試 LINE 群組輸入：「活動籌備專案的場地確認期限改為【自訂新期限】，負責人維持不變。」再輸入：「【自訂候選日期】可以考慮作為公開報名日，但目前尚未正式決定。」請先填入新期限與候選日期，讓新期限晚於原期限，三個日期合理且彼此一致；原期限、新期限與候選日期都是工作日期，不是 LINE 訊息的發生日期。使用下載檔才以 2026-04-21、2026-04-25 核對。輸入 #寄出紀錄，等 Bot 回覆寄送完成。

  4. 確認 Gmail 與 Sheets

    開啟 Gmail → 重新整理 → 找到主旨 [LINE紀錄][群組名稱] 日期 → 點開正文，確認有兩句對話及實際訊息日期。再到 Google Sheet 的 messages 核對兩列 group_id 屬於目前群組、message 保留原文，寄送後 sent = TRUE。

    你現在應該看到Gmail 正文有兩句 LINE 更新；Sheets 對應兩列為 TRUE。若 Email 未出現，先停在 LINE → Gmail 路徑排錯，不要進入 ChatGPT。

  5. 回到同一個專案主對話

    開啟 ChatGPT Desktop App → 左側欄的 Projects／專案 → 活動籌備 Project → 開啟「活動籌備｜工作記憶」對話。確認 Google Drive 與 Gmail 可由 Plugins／Apps（依目前介面顯示名稱為準） 使用 → 貼上 Prompt 2 的「後續更新簡短版」，指定本次實際紀錄日期並要求重新讀取兩邊正文。

    開啟 Prompt 2

  6. 核對判斷與來源

    下載檔的固定答案是場地期限 2026-04-18 → 2026-04-21，負責人仍為活動窗口，2026-04-25 只是候選。自行產生的紀錄則應呈現你實際設定的原期限 → 新期限，候選日期不能列為已定案。答案必須列出實際讀取的 Google Drive 文件與 Gmail 郵件，排除其他專案；任一來源無法存取時須明說。

    你現在應該看到同一則回答同時引用 Drive 完整逐字稿與 Gmail [LINE紀錄] 正文，專案歸屬與版本判斷正確，且列出需要人工確認的事項。到這裡才算手動跨來源驗證成功。

第二階段：使用互動式專案工作助理，完成最新工作記憶與週報

只安裝一個 project-work-assistant Skill。它包含整理會議、確認決策變更、更新工作記憶及產生週報四種服務。啟動後選服務、回答缺少的問題即可；已明確說出任務時直接進入該服務，不必撰寫四份提示詞。

  1. 下載並安裝一個 Skill

    開啟一鍵安裝教學，下載專案工作助理 ZIP。讓 Codex 安裝並驗收唯一的 project-work-assistant 資料夾；完整的 references 與範例也必須保留。

  2. 在 Codex 啟動

    複製下方指令並貼到 Codex。若只輸入指令，助理會列四種服務；你也可以直接說「幫我產生本週週報」，它會直接進入週報流程。

  1. 第一次選「3. 更新最新專案工作記憶」

    助理會先檢查目前對話已確認的專案、允許來源與日期範圍；缺少才依序問「這次要整理哪個專案？」「你想整理哪個期間？」「這次要使用哪些資料？」。本課可選「活動籌備專案」，指定這次實際可讀取的會議與 LINE 紀錄。選擇「根據指定來源的實際紀錄日期」時，先讓助理從正文找出範圍，再由你確認。

  2. 提供 Codex 可讀取的來源

    若 Codex 無法讀取 ChatGPT Project 中已連接的 Google Drive／Gmail，請下載或提供兩份來源正文：01_meeting.txt 與 02_line_email.txt，放進 Codex 可讀的資料夾並明確指定。不要假設 Codex 與 ChatGPT Project 的權限互通；無法存取來源時要先提供檔案，不能把未讀資料當成已讀。

  3. 核對本次工作記憶

    下載的虛構練習檔分別記於 2026-04-16 與 2026-04-17；固定答案是場地確認期限 2026-04-18 → 2026-04-21、負責人仍為活動窗口、2026-04-25 只作候選公開報名日。核對輸出是否附上實際讀取的兩份來源，沒有完成證據就不能標成已完成。

  4. 第二次快速使用

    在同一個已確認專案的對話，直接說「幫我產生本週週報」。助理應沿用仍有效的專案與允許來源，只詢問缺少的資訊，重新讀取正文；週報的本週一至今天依執行當下的當地日期計算。也可說「更新一下專案」，但若上次成功更新截止日不明，助理仍須先問。

固定日期只屬於下載案例以上 2026 年 4 月日期只用於講義虛構練習檔及固定答案。若你自行建立新的 Google Meet 與 LINE 紀錄，請使用來源正文中的實際發生日期；工作期限、Skill 資料期間、週報期間與排程執行時間分開確認。期間不明就請助理詢問，不照抄講義日期，也不把未來紀錄寫成已發生。

同專案設定可在你同意後，保存非敏感的專案名稱、來源參照、時區與已驗收的成功截止日；不同專案分開保存。更新失敗不能推進截止日。若無寫入權限，只沿用目前對話確實可確認的資訊。完整的互動示範、設定保存與切換專案說明在附錄。沒有 Skill 功能時，使用四份 Prompt 相容版，原本的來源與衝突規則仍適用。

第三階段：設定跨來源週期排程

Google Drive + Gmail [LINE紀錄] → ChatGPT → 跨來源工作記憶

確認排程設定介面建立排程時，Prompt 必須明確描述排程意圖與執行頻率。如果只要求「更新工作記憶」，ChatGPT 可能將它視為一般的一次性任務。貼上本教材 Prompt 後，請確認畫面有出現「重複／每天／時間」等排程設定，本課示範設定為每天 15:00、時區 Asia/Taipei 後儲存。介面名稱與呈現方式可能隨版本調整。

  1. 再次確認排程前提

    Drive 已有可讀取的會議完整逐字稿、Gmail 已有可讀取的 [LINE紀錄]，而且上一階段的專案主對話能實際讀取兩邊。任一項未完成就先回去排錯。

  2. 在 Desktop App 開啟 Scheduled

    在 ChatGPT Desktop App 找到 Scheduled／排程 入口並開啟。若目前介面沒有此入口，可用相同帳號從 ChatGPT Web 備用入口查看；不同版本的入口位置與名稱請依目前介面為準。若兩邊都沒有，可能是帳號、plan、region、workspace、管理員政策或目前介面版本尚未提供；這不代表你操作錯誤，也不要改在 Codex 建立。

  3. 建立新排程

    在 Scheduled 頁按建立新任務，或選 Try your own（實際名稱可能隨介面版本調整）→ 貼上下方 Prompt 3 → 把 ＿＿＿＿專案 換成要持續追蹤的實際專案名稱 → 確認排程設定顯示重複、本課示範的每天 15:00 與 Asia/Taipei → 儲存；實際使用可自行調整時間與頻率。若系統先建立對話再讓你設定時間，依確認卡或時鐘按鈕完成排程。

  4. 依需求設定任務通知

    儲存排程後，到 ChatGPT → 設定 → 通知 → 任務，依需求開啟推播、電子郵件或兩者。Prompt 負責定義任務要做什麼；Email／Push 屬於 ChatGPT 帳號層級的通知設定。兩者不是同一件事，可用的通知管道也可能依帳號、裝置與目前介面而異。

    通知不是 Prompt 控制A. Gmail Connector：用來讀取 [LINE紀錄] 等工作來源。
    B. ChatGPT Task Email Notification：由 ChatGPT 系統通知某次排程任務已有更新／結果。這不是透過課程中的 Gmail Connector 主動寄信，也不可因為 Prompt 寫了「通知」就假設 Email 或 Push 一定送達。

  5. 確認排程管理入口

    建立後可回到左側欄的 Scheduled／排程 查看、編輯、暫停或刪除任務。若使用 ChatGPT Web 備用入口，另一條可能的路徑是 Settings／設定 → Notifications／通知 → Manage tasks／管理任務；從個別任務對話的更多選單也可能看到 See scheduled tasks／查看排程任務。

這是課程示範設定，不代表每個人都必須選擇下午三點。實際使用時，可以按照自己的工作習慣調整執行時間與頻率；若改動，Prompt 3 的週期與資料時間窗也要同步調整並重新核對。實際執行時間由排程設定控制；資料日期範圍由任務提示詞和來源紀錄決定，不要混為一談。

建立後驗證

排程建立完成不等於已驗收。排程與 Skill 是不同功能；安裝 Codex Skill 不會自動讓這個 ChatGPT 排程使用它。請分開確認排程有執行、指定來源有讀取、結果判斷正確、通知有送達四個層級。

  1. 確認下一次執行時間

    回到排程／任務頁，確認任務顯示正確的下一次執行時間，並確認任務處於啟用狀態。

  2. 確認時區與執行時間

    核對排程使用的時區與預定時間。本課示範每天 15:00、Asia/Taipei；若你選擇其他時間或時區，以自己儲存的排程為準，核對帳號或裝置顯示是否一致。

  3. 再次確認通知設定

    到 設定 → 通知 → 任務，確認需要的推播與電子郵件已開啟。這只設定通知管道，不會改變 Prompt，也不會替代任務執行結果。

  4. 確認 Plugins／Apps 權限

    在 ChatGPT Desktop App 開啟 Settings／設定 → Plugins／Apps（依目前介面顯示名稱為準），確認 Google Drive 與 Gmail 已連接；若使用 ChatGPT Web 備用入口，也在該介面確認連線狀態。若排程關聯對話提供 +／工具選單，也要確認這兩個來源可選用。排程能否使用來源取決於你的 account、plan、region、workspace 權限、管理員政策與當下可用的 Plugins／Apps；一般對話能使用，不代表每個排程環境都必然能用。

  5. 檢查第一次執行

    第一次排程執行後，不要只看 Email。先回到 ChatGPT 的排程／任務頁，確認任務是否真的有執行、是否有新的執行結果，再打開結果核對指定專案、實際時間範圍、Drive 文件、Gmail 郵件、已確認決策、待辦、變更與排除資料。若只讀到一邊，或混入其他專案，這次不能算完整跨來源更新。若指定結束日晚於執行日，後段尚未發生，不得寫成查無資料。

    你現在應該看到Scheduled 頁列出任務名稱、下一次執行時間與頻率；第一次結果清楚區分「已讀取且找到相關資料」「指定已發生期間內未找到相關資料」「目前無法存取此來源」與「該期間尚未發生」。有新資料時只更新指定專案，沒有新資料時明確說「本次週期沒有新的工作記憶需要更新」。

  6. 再確認下一個週期

    如果是每天、每週等重複排程，不要因為第一次成功就判定設定完成。至少再確認下一個週期是否真的再次執行。

判斷問題的順序
  1. 第一層：排程有沒有實際執行？
  2. 第二層：指定 Drive／Gmail 來源有沒有實際讀取？
  3. 第三層：結果的專案、日期、決策與待辦是否正確？
  4. 第四層：Email／Push 有沒有送達？
排程執行、資料讀取、結果正確與通知配送是四個不同層級；沒有收到 Email，不能直接判定排程失敗。
重要：第一次通知不是長期保證第一次收到 Task Update，不代表重複排程之後每次都一定會正常執行。建立 Daily／Weekly 重複任務後，至少要確認第一次執行成功，並再檢查下一次週期仍有執行；不要把第一次 Email 當成唯一驗收條件。

第四階段：最終成果驗收與課程總結

完成最後一集時，用下列清單回查來源與結果；任何「已完成」都要有本次實際讀到的證據。

  1. 會議完整逐字稿已儲存至 Google Drive，並可打開正文。
  2. LINE Bot 紀錄已寄送至 Gmail，郵件正文含後續更新。
  3. ChatGPT 能實際讀取指定的 Google Drive 與 Gmail 資料來源。
  4. 使用下載練習檔時，能辨識 4/18 → 4/21 的期限變更與 4/25 候選；自行建立紀錄時，能辨識實際設定的原期限 → 新期限與候選日期。
  5. 能產出最新專案工作記憶，列出決策、待辦、負責人、期限、未決事項與來源。
  6. 可用 Skill 或 Prompt 相容版產出有日期範圍與來源的專案週報。
  7. 週期排程已建立，能檢查執行時間、實際結果與下一週期。
  8. 重要結果已人工核對原始逐字稿與郵件正文，並分開驗收通知。
課程總結你已完成一套可重複運用的工作訊息整理系統：收集會議與 LINE 紀錄，跨來源確認最新決策，用 Skill 或 Prompt 形成工作記憶與週報，再依可用環境安排週期檢查。每次仍要核對實際讀到的來源與重要結論。
