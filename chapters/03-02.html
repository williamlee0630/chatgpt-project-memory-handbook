第 3 章｜建立跨來源工作記憶

3-2 驗收並持續更新工作記憶

回到原始來源抽查第一版結果；確認後留在同一個專案主對話，用短訊息更新下一個日期範圍。

基礎篇7 分鐘核心實作

人工驗收第一版

  1. 抽查已確認決策

    從答案挑至少兩筆已確認決策 → 回到標示的會議逐字稿或 LINE 來源 → 搜尋原句 → 確認有「決定、確認、照此執行」等定案語意。只有討論或建議時，要求 ChatGPT 移到未決事項。

  2. 抽查每一筆待辦

    逐欄核對事項、負責人、期限、來源與目前進度。來源沒寫人名或日期時，正確結果是「待確認」，不是合理猜測。

  3. 檢查決策變更

    每筆變更都要看得到 原決定 → 新決定，並能回查兩邊來源。LINE 的時間較晚，不得因為時間較晚就自動覆蓋會議決策；必須有「改為、延期至、取消、改由」等修改語意。

  4. 檢查候選與衝突

    搜尋答案中的「候選、暫定、考慮、建議、可能、預計」，確認沒有被放進已確認決策。兩個來源不同但證據不足時，應列入衝突提醒或需要人工確認。

  5. 核對來源與排除資料

    確認答案列出的文件名稱、郵件主旨或 LINE TXT 真的屬於本專案與日期範圍；測試訊息、日期外資料與重複會議應出現在排除資料，而不是被悄悄混入。

    你現在應該看到每筆重要結論都能回到來源；缺資料的欄位保留「待確認」，候選沒有被定案，真正修改才列為決策變更。

修正方式

若抽查發現錯誤，直接在目前對話指出「哪一筆、正確來源、應改成什麼」。練習案例可寫成：「4/25 只是候選公開報名日，請移出已確認決策，保留在未決事項。」修正後再抽查一次。重要日期、金額、客戶承諾與正式發布時程仍由你確認。

只有人工確認後，才保存為 Project source

  1. 確認要保存的是最終版本

    先完成上方抽查與修正，確認來源、日期、負責人、決策與候選狀態都已核對。只有人工確認過的結果可以保存；ChatGPT 第一次產生的內容只是待驗收草稿。

  2. 從網頁版保存

    在 ChatGPT 網頁版的目前專案主對話中，找到人工確認過的最終答案 → 開啟答案旁的選單 → 選 Save to project／Add to project sources（依目前介面顯示名稱為準）→ 確認加入目前的「工作訊息整理」。若帳號沒有這個選項，可保留在已驗收的主對話中，不要把未驗收內容另行保存。

  3. 回到 Sources 核對

    開啟「工作訊息整理」的 Sources／來源，確認保存的項目名稱與內容是剛才驗收完成的版本。

    保存不等於定案Save to project／Add to project sources 只是在 Project 中保留可再次使用的內容，不代表內容已自動成為正式專案狀態。日後來源有更新時，仍要重新比較並人工確認。

下一次持續更新

  1. 回到同一個專案主對話

    開啟 ChatGPT 網頁版 → 左側欄的 Projects／專案 → 工作訊息整理 → 開啟 2-1 建立的目前專案主對話，例如 網站改版專案｜工作記憶。不要按 New chat，也不要重新貼 Prompt 1 或 Prompt 2 全文。

  2. 準備新的日期範圍

    基礎版先把新逐字稿與新 LINE TXT 附加到這個對話；進階版確認 Google Drive 與 Gmail 仍可存取。日期只填本次新增紀錄的實際開始與結束日期。

  3. 貼上後續更新簡短版

    複製下方短版 → 填入同一專案名稱與新的日期範圍 → 送出。這張卡片屬於 Prompt 2 的日常用法，不是新的編號 Prompt。

  1. 比較更新前後

    答案應保留已確認的前次專案脈絡，並標出新增、完成、決策變更、待辦變更、未決與衝突。收到新資料不代表舊內容可以直接刪除。

    你現在應該看到新的日期範圍被加入同一份工作記憶；未變更項目延續、完成項目有證據、變更保留前後關係。

基礎篇完成成果

  • Google Meet + Tactiq 取得完整繁中逐字稿
  • LINE 手動匯出 TXT
  • Prompt 2 在專案主對話建立第一版工作記憶
  • 人工抽查決策、待辦、變更、候選與來源
  • 後續留在同一對話，用簡短版持續更新
