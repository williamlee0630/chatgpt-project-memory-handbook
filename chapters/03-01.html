第 3 章｜建立跨來源工作記憶

3-1 合併會議與 LINE 紀錄

先證明兩個來源都讀到了，再判斷哪些資料屬於同一工作。

基礎篇8 分鐘跨來源整理已實測

準備兩份來源

來源本課解讀基礎版提供方式
Google Drive Tactiq Transcript會議當下版本連接 Drive，或開啟 Docs 後複製／下載再上傳
LINE TXT會後補充或後續更新上一節手動匯出並上傳

實作

  1. 指定專案與時間

    明確寫出專案名稱、會議日期與 LINE 日期範圍。不要只說「幫我整理最近的」。

  2. 要求逐一確認來源

    請 ChatGPT 先列出會議文件名稱與 LINE 檔名，再開始整理；任何一份讀不到就停止跨來源結論。

  3. 辨識是否同一工作

    比對專案名稱、會議主題、參與者與具體事項。僅日期相同不是充分條件。

  4. 排除重複與雜訊

    同一場會議可能因手動 Run 重複建立文件，要先去重；「測試 123」「機器人上線」等訊息若不屬於工作內容，列入排除。

  5. 套用版本規則

    LINE 時間較晚不代表一定推翻會議。只有「改為、延期到、取消、由 A 改成 B」等明確語意才列決策變更。

執行跨來源整理

完成上方來源確認後，使用這份核心 Prompt 產生可回查來源的工作記憶。

已實測案例會議原決定「第一版 10/20 完成」，LINE 後續明確說「改為 10/23 完成」，ChatGPT 正確列為「10/20 → 10/23」；「10/30 候選上架日」仍保留為候選，沒有誤判為決策。

如何驗證成功

  • 答案列出本次讀取的會議與 LINE 檔案
  • Drive 內容被視為會議當下版本
  • LINE 明確修改才成為新決定
  • 候選、測試訊息與重複文件沒有混入正式決策
