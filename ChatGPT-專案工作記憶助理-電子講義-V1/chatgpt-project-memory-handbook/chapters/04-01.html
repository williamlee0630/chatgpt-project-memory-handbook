4-1 Bot 資料流與部署架構

進階篇把「手動匯出 LINE TXT」換成可重複使用的訊息保存與寄送流程。你不需要從零寫 Bot。

進階篇5 分鐘多群組流程已實測

每個服務只做一件事

服務用途不負責
LINE Official Account讓 Bot 加入群組並送出事件不保存所有歷史訊息
Vercel提供公開 HTTPS Webhook 並執行程式不當永久資料庫
Google Sheets保存 Bot 加入後的新文字訊息與 sentAt不做內容判斷
Gmail把每個群組的 LINE 紀錄送入 ChatGPT 可搜尋的入口不接收 Tactiq Transcript
ChatGPT與 Drive 會議逐字稿合併、判斷決策與衝突不自行補缺少的資訊

範本的實際行為

  • Bot 只處理 加入群組後的新文字訊息。
  • 每則訊息保存 groupId、群組名、發言者、時間、文字、messageId 與 sentAt。
  • 圖片、貼圖、檔案、收回訊息與加入前歷史不在本課主流程。
  • 同一隻 Bot 可加入多個群組，資料以 groupId 隔離。
  • 群組輸入 !寄送紀錄，只寄出目前群組 sentAt 空白的紀錄。
  • Gmail 主旨固定為 [LINE紀錄][群組名稱] YYYY-MM-DD。

部署前檢查

  • 可以登入 LINE Developers 與 LINE Official Account Manager
  • 可以建立 Google Cloud 專案、服務帳號與 Google Sheet
  • Google 帳號已開啟兩步驟驗證，可建立 Gmail App Password
  • 可以登入 GitHub 與 Vercel
  • 準備兩個測試 LINE 群組；不要先用正式客戶群組
密鑰安全Channel Secret、Access Token、服務帳號 JSON 與 Gmail App Password 都是密鑰。只放 Vercel Environment Variables，不貼進講義、聊天室、GitHub 或畫面截圖。
