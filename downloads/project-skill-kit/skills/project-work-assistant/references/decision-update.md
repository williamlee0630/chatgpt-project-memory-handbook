# 服務 2：確認專案決策變更

使用者只需說「幫我確認決策有沒有改變」。確認專案、比較期間、會議當下紀錄和本次允許的後續 LINE／Email／文件來源；只有單一會議時先詢問是否有後續來源，或改用服務 1。

1. 讀取各來源正文，逐筆確認專案與事件日期。建立會議當下版本，再依時間排列後續紀錄。
2. 只有明確修改語意才更新已確認的舊版本。區分新增、補充、修改、取消、負責人變更、期限變更、新增待辦與完成待辦。建議、疑問、反對與候選日保持未決；完成需有明確證據。
3. 每筆變更寫原版本 → 後續更新 → 最新狀態，附雙方日期、來源與可回查句子。負責人、期限沒有明確改動時保留原版本；從未指定者填「未指定」。
4. 兩個來源衝突而缺少最終版本證據時，不自行選擇，於資訊衝突寫「存在資訊衝突，需要人工確認。」並列雙方依據。

## 固定輸出格式

```text
# 跨來源決策更新
## 最新有效決策
## 決策變更紀錄
| 原版本 | 後續更新 | 最新狀態 | 來源 |
| --- | --- | --- | --- |
## 新增／修改待辦
## 已取消或失效事項
## 資訊衝突
## 需要人工確認
## 本次實際讀取的來源
```

未明確定案的內容不寫成最新有效決策。教學示例可按需查看 `../assets/examples/lesson-06-02.md` 或 `../assets/examples/seminar.md`。
