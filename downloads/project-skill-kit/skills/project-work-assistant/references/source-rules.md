# 共用來源與正確性規則

四種服務都要遵守本頁；讀取所選服務規則後再執行。

## 專案與來源邊界

- 只處理使用者確認的單一專案及本次允許來源。依專案名稱、主題、正文、具體工作事項與上下文逐筆判斷歸屬；相同人物、日期、寄件者或 LINE 群組成員不能單獨證明同一專案。明確無關者排除，歸屬不明者列「需要人工確認」。
- 新事實只能來自本次允許、實際讀取正文、落在本次期間且通過專案歸屬檢查的來源。只處理本次允許來源；未指定的資料不搜尋、不讀取、不納入。
- 不依檔名、郵件主旨、搜尋摘要或片段形成結論；這些只能找候選，必須打開正文。不得用過去回答、模型記憶、其他聊天、其他 Project、常識或其他專案補入新事實。既有工作記憶只能用於同一專案內的前後比較，不能提供新增事實。

## 日期與來源狀態

- 依執行環境的實際當地日期與已確認時區決定已發生期間。來源事件日期與資料期間分開記錄；待辦截止期限及排程執行時間都不是來源發生日期。
- 若指定期間延伸到未來，只處理截至今天已發生的部分，對未來部分標「該期間尚未發生」，不能說「查無資料」或假裝讀過。來源日期或期間不明時先詢問／請使用者確認。
- 每個允許來源標記其中一種狀態：已讀取且找到相關資料；已成功存取但指定已發生期間內未找到相關資料；目前無法存取此來源；該期間尚未發生。權限、連線或工具錯誤應寫「目前無法存取此來源」，請使用者貼上或上傳，不描述為沒有資料。
- 允許 Google Drive 時，搜尋並打開相關 Tactiq／Google Meet 文件全文。允許 Gmail 時，以 `[LINE紀錄]` 等主旨找候選郵件，打開郵件正文。使用者提供的 LINE TXT、Email 或其他文件同樣核對原文、事件日期與專案歸屬。

## 決策、待辦與版本

- 會議逐字稿是會議當下版本，不一定是最終版本；較晚的 LINE、Email 或文件不自動覆蓋。沒有固定的「LINE 一定高於會議」優先序。
- 先按事件日期建立版本時間線。只有後續內容明確說「修改」「改成」「最後決定」「不做了」「延到」「延後」「取消」「改由」「改為」「上次的決定修改為」等，才更新對應舊決策、期限、負責人或狀態；保留舊版本 → 新版本、日期、來源與可回查原句。跨更新期間仍保留這項變更。
- 「候選」「暫定」「考慮」「建議」「可能」「預計」、疑問或反對意見本身不是已確認決策。只有明確完成證據才標完成。沒有明確負責人或期限填「未指定」；缺少其他關鍵狀態列「需要人工確認」。不自行補人名、日期、數字、完成百分比或承諾。
- 來源互相矛盾且無法確認哪版有效時，不選邊；列雙方日期、來源與缺少依據，寫「存在資訊衝突，需要人工確認。」並交使用者確認。

## 輸出前核對

按所選服務的固定格式輸出。重要結論附事件日期、來源名稱與能回查的句子。明列實際讀取與排除的資料；來源無法存取、沒有相關資料、期間尚未發生分別說明。只對已通過上述檢查的內容下結論。
