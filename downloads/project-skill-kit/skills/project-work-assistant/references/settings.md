# 可選的每專案設定

設定只用來減少重複提問，不是資料來源，也不授予 Google Drive／Gmail 等權限。只在使用者明確同意，且目前專案工作資料夾有寫入權限時保存；無法寫入時說明只能沿用目前對話內確實可見的設定。

## 儲存

1. 請使用者指定目前專案的工作資料夾，確認其屬於指定專案且可以寫入。不同專案各自使用獨立資料夾與 `project-work-assistant.settings.json`；若名稱相同或資料夾歸屬不明先詢問，不把兩個專案合併。不要遍歷其他專案尋找設定。
2. 使用者同意後，僅存非敏感欄位：`project_name`、`source_refs`（使用者允許的非敏感來源位置或代稱）、`timezone`、`last_successful_through`。不得儲存密碼、Token、API key、郵件內容、逐字稿或其他敏感憑證。若來源參照本身含秘密，改用不含秘密的代稱或不保存。
3. `last_successful_through` 僅在該專案的來源實際讀取、任務成功輸出且使用者確認驗收後寫入。更新失敗、來源無法存取、資訊不足或尚未驗收時不能前推截止日；可保留舊值。使用原子寫入或安全的暫存檔置換，避免半寫檔案。

```json
{
  "project_name": "活動籌備專案",
  "source_refs": ["本專案已授權的會議資料夾", "本專案指定的 LINE 紀錄"],
  "timezone": "Asia/Taipei",
  "last_successful_through": null
}
```

上例只示範欄位，日期與來源代稱均須來自使用者實際確認的專案；不得把講義日期寫成預設值。

## 沿用與清除

讀取設定時先確認檔案屬於目前專案、來源仍由使用者允許且可讀、時區仍適用；過期或無法確認的欄位請詢問。設定檔只能確認來源位置及上次成功截止日，本次新事實仍須重讀原始正文。切換專案要使用新專案設定，不沿用舊專案的來源或截止日。

使用者要求清除時，先確定目前專案與設定檔位置，再只清除該專案的 `project-work-assistant.settings.json`；無法確認檔案歸屬時先問，不刪其他資料或其他專案設定。清除後同對話仍可使用明確可見的設定，但不宣稱持久化仍存在。
