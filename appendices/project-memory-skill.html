沿用原有的專案工作記憶更新 Skill，持續比較同一專案的前後版本。

3. 建議操作順序

  1. 先完成本課 Project 與來源設定

    依第 1～3 章取得逐字稿、LINE 紀錄，建立 Project 與專案主對話。

    從本頁選一份 Prompt，填入目前專案、日期與允許來源，實際讀取正文。

    再次指定相同專案與來源，看看 Prompt 與 Skill 是否遵守同一套判斷規則。

5. 共同判斷規則

  • 只處理本次明確指定的專案與實際讀取來源；同一人物不代表同一專案。
  • 討論、建議、候選與未定方案，不寫成已確認決策。
  • 負責人、期限、完成、取消與進度都要有來源依據；缺少時寫「未指定」或「需要人工確認」。
  • 先看時間順序，但較晚不代表自動覆蓋。只有明確修改語意才更新舊版本。
  • 兩個來源衝突而無法確認最終版本時，寫「存在資訊衝突，需要人工確認。」
結果怎麼看先看「本次實際讀取的來源」是否包含你指定的資料，再回查已確認決策與待辦的原句。接著核對原決議 → 新決議、負責人與期限；未決或衝突應留在「需要人工確認」，不要直接當成定案。

6. 本課說的「自動化」到哪裡？

可達到的流程指定來源自動收集＋固定週期重新搜尋與整理＋形成最新版工作記憶。這不表示 ChatGPT 能取得所有資料，或把每次結果永久自動寫入 Project。
可較自動化處理仍需前處理
Tactiq → Google Drive；LINE Bot → Google Sheets／Gmail；ChatGPT 在取得權限後定期搜尋指定 Drive／Gmail 來源並整理。紙本手寫筆記、單獨錄音檔、尚未轉成文字的內容，以及 ChatGPT 無權存取的系統，須先數位化、轉錄或匯入可讀來源。
