工具箱

排錯中心

先找「最後一個成功的節點」，再檢查下一步；不要一次重設所有帳號。

Tactiq

Google Meet 有講話，但 Tactiq 沒有 Transcript

  1. 確認瀏覽器的 Tactiq 擴充功能已啟用。
  2. 確認 Meet 麥克風正常，音量指示有反應。
  3. 確認 Meet 字幕／會議語言與實際語言一致。
  4. 在 Tactiq 選擇 Chinese / Mandarin Traditional。
  5. 仍無文字時，離開 Meet 後重新加入，再念一個完整句子。

會議結束後 Drive 還沒有文件

  1. Automatic Workflow 可能仍在處理延遲中，不承諾固定完成時間。
  2. 到 Tactiq → My Meetings，確認該場會議已存在完整 Transcript。
  3. 查看 Workflow Activity，確認是等待、失敗或成功。
  4. 不要過早重複手動 Run。
  5. My Meetings 已有 Transcript 且 Activity 未成功時，用 My Meetings → 選擇會議 → Run Workflow 作為備援。

Drive 出現兩份相同文件

可能是 Automatic 尚在等待時又手動按 Run。先比對會議名稱、日期與 Transcript；保留一份，刪除重複檔。下次先確認 Activity 後再手動執行。

Email 無法取得完整 Tactiq Transcript

正式課程不走這條路。Email team members／Compose text from template 即使能寄信，也未實測輸出完整 Transcript；請使用已驗證的 Google Drive Integration。

LINE／Vercel／Google

LINE Verify 失敗

  • Webhook URL 必須是部署後的 HTTPS 網址，並以 /callback 結尾。
  • 六個環境變數必須全部存在且名稱完全正確。
  • 修改環境變數後必須到 Deployments 執行 Redeploy。
  • LINE_CHANNEL_SECRET 不可有多餘空白。
  • 確認最新 Vercel Deployment 顯示 Ready，再回 LINE Developers Verify。

Sheets 沒新增資料

  • 工作表必須叫小寫 groups 與 messages。
  • groups 表頭必須依序為 group_id、group_name、receiver_email。
  • messages 表頭必須依序為 webhook_event_id、message_id、group_id、user_id、display_name、message、created_at、sent；欄位順序不可交換。
  • Service Account JSON 的 client_email 必須是試算表編輯者。
  • GOOGLE_SHEET_ID 只填網址 /d/ 與 /edit 之間的字串，不可填整條網址。
  • Bot 必須已加入群組，且只有加入後的一般文字會寫入 messages。
  • #設定信箱、#查看信箱、#寄出紀錄 都是控制指令，不會寫入 messages。
  • 仍沒有資料時，查看 Vercel Logs 的最新 Function 錯誤。

Gmail 沒收到信

  • 先在目前群組使用 #設定信箱 <你的實際 Email>；使用半形 #，指令後放一個一般半形空格，Email 必須能實際收信。
  • 使用 #查看信箱 確認目前群組地址。
  • 必須使用 #寄出紀錄 才會寄出尚未寄送的訊息。
  • GMAIL_APP_PASSWORD 必須是 Google App Password，不是一般 Gmail 密碼；貼入前移除顯示用空格。
  • 寄件地址使用 GMAIL_ADDRESS，且必須和建立 App Password 的 Google 帳號一致。
  • Email 失敗時，對應訊息的 sent 應維持 FALSE，修正設定後可再次寄送。

多群組混用

  • 檢查 groups 中每列的 group_id；兩個群組必須不同。
  • 每個群組都要分別執行 #設定信箱，再用 #查看信箱 核對。
  • 不可用群組名稱作為唯一識別，群組名稱可能重複或更改。
  • #寄出紀錄 只會處理目前 group_id 且 sent = FALSE 的資料。
SMTP 成功後標記失敗的已知限制如果 Email 已經由 SMTP 成功送出，但後續 Google Sheets 的 sent = TRUE 更新失敗，該訊息可能維持 sent = FALSE。此時再次執行 #寄出紀錄可能造成重複 Email；先檢查收件匣與 Sheets 狀態，再決定是否重試。本課只揭露限制，不改變正式寄送邏輯。

LINE Bot 錄課驗收情境 A～J

A. GOOGLE_SERVICE_ACCOUNT_BASE64 無效

  • 確認使用剛下載的原始 Service Account JSON，並確認 JSON 的實際檔名與完整路徑。
  • 在 PowerShell 重新執行下列產生指令；禁止使用線上 Base64 converter。
重新產生並複製 Base64
[Convert]::ToBase64String([IO.File]::ReadAllBytes("完整JSON路徑")) | Set-Clipboard
  • PowerShell 沒有顯示大量文字是正常的，結果已直接複製到剪貼簿；立即前往 Vercel，貼入 GOOGLE_SERVICE_ACCOUNT_BASE64 的 Value。
  • 貼入 Vercel 前不要再複製其他文字，否則剪貼簿內容會被覆蓋；若已被覆蓋，重新執行 PowerShell 指令即可。
  • 可切換 Value 的顯示／遮蔽狀態確認已貼入長字串，但看到長字串不代表 Base64 有效性的技術驗證。最終是否設定正確，以部署與實際 Google Sheets 寫入測試為準。

B. Google Sheets 403 / permission denied

  • 確認 Google Sheets API 已 Enabled。
  • 確認 JSON 的 client_email 已加入該 Google Sheet，權限是 Editor／編輯者。
  • GOOGLE_SHEET_ID 只放 /d/ 與 /edit 中間的 ID，不是整條 URL。

C. Gmail SMTP 535 / authentication failed

  • 使用 App Password，不是一般 Google 密碼。
  • GMAIL_ADDRESS 必須和建立 App Password 的帳號一致，App Password 貼入前移除空格。
  • 如果最近修改 Google 一般登入密碼，重新建立 App Password。
  • 確認帳號不是被政策限制而無法建立 App Password。

D. App Password 找不到

  • 檢查是否只使用 Security Key 進行兩步驟驗證。
  • 檢查公司／學校 Organization account 是否禁止 App Password。
  • 檢查是否已啟用 Advanced Protection。

E. Vercel Environment Variable 看起來有填但仍失敗

  • 逐字檢查 Name 大小寫。
  • Value 只放真正的值，不含 NAME=、單引號、雙引號、前後空白或多餘換行。
  • 修改後回原 Project 執行 Redeploy；不要重新 Drop ZIP。

F. Deployment Ready，但網址瀏覽器看到 404

  • 本專案沒有 GET health page，根網址 404 不代表失敗。
  • 改用 LINE Verify 與群組新文字是否寫入 Sheets 判斷。

G. LINE Bot 無法加入群組

  • 確認 Allow bot to join group chats 已開啟。
  • 確認群組裡是否已有其他 LINE Official Account；同一時間只能有一個。

H. Verify Success 但 Sheets 沒資料

  • 確認 Use webhook 已開啟且 Bot 已加入群組。
  • 傳送加入後的新文字；舊訊息、圖片、貼圖、私訊、room 或其他非文字不會寫入。
  • 查看 Vercel Logs／Deployment Logs 的最新 Function 錯誤。

I. sent = TRUE 但收件匣沒看到

  • 檢查 Spam／Junk 與所有郵件。
  • SMTP 接受寄送不代表郵件一定立即出現在主要收件匣。

J. ChatGPT 顯示 Drive / Gmail 已連接，但找不到資料

  • Connected 不代表一定有該檔案或郵件的讀取權限。
  • 確認連接的 Google 帳號、app/plugin 可用性，以及檔案／郵件確實位於指定帳號與日期範圍。
  • 無法存取就改走人工上傳或手動提供正文，不得假裝讀過。

ChatGPT

答案看起來完整，但只讀到一個來源

改用附錄完整版 Prompt，要求固定輸出「本次實際讀取的 Google Drive 資料」與「本次實際讀取的 Gmail 資料」。任一來源無法存取就停止跨來源結論。

把候選日期當成正式決策

要求引用原句，並重新套用規則：候選、暫定、考慮、建議、可能、預計均不得視為正式決策。
